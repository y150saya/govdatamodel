# データ定義ガイドライン

データモデル全体で共通して適用される、データ型の定義や記述項目の標準化指針を定義します。将来的に他の共通定義項目も本ドキュメントに追加されます。

---

## 1. 共通テキスト属性（概要・説明・備考）

テキストの自由記述属性である「概要 / abstract」「説明 / description」「備考 / remark」について、一貫した方針で整備・運用するためのデータ定義です。デジタル庁の政府相互運用性フレームワーク（GIF）の定義に準拠しています。

### 1.1 定義一覧

| 属性名（和名 / 英名） | GIFの定義 | 公開範囲 | 想定文字数・用途 |
| :--- | :--- | :--- | :--- |
| **概要 / abstract** | 公開可能概要情報 | **一般公開**（外部連携可） | **短文（〜50文字程度）**<br>検索結果一覧やリスト画面のサマリー等で使用する、対象のキャッチコピーや簡潔な要約。 |
| **説明 / description** | 公開可能詳細説明 | **一般公開**（外部連携可） | **中〜長文（100文字〜）**<br>詳細表示画面等で使用する、対象の機能・特徴・歴史などの詳細な説明テキスト。 |
| **備考 / remark** | 備考 | **内部管理**（基本非公開 / 制限公開） | **文字数制限なし**<br>データソースの出所や更新履歴、システム管理上の引き継ぎ・注意事項等の補助メモ。 |

### 1.2 データ作成・整備時の入力優先ルール

データの作成時および既存システムからのデータマッピング時には、以下の優先ルールを適用します。

1. **基本入力項目**: 対象の本質的な説明は、まず **「説明（`description`）」** に詳細を記入します。
2. **概要の省略ルール**: 「概要（`abstract`）」は任意項目です。データ項目が用意できない場合は省略（Null）として構いません。その場合、システム表示側で「説明」の先頭部分を自動カットアップして代替表示することを推奨します。
3. **備考の管理区分**: システム間で公開したくないログ情報や内部的な注意書きは、必ず **「備考（`remark`）」** を使用し、「説明」や「概要」には混入させないでください。

### 1.3 実データへのマッピング具体例（建物モデルの例）

*   **概要 (`abstract`)**: `「商業施設とオフィスからなる15階建て複合ビル」`
*   **説明 (`description`)**: `「1F〜3Fに商業テナント、4F以上にオフィスを配した複合商業施設。地域コミュニティの交流を促す広場を併設し、省エネ基準を満たしたスマートビルです。」`
*   **備考 (`remark`)**: `「令和7年度都市計画調査データよりインポート。点検日：毎月第2日曜日」`
