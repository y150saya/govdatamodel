# 自治体施設管理データ標準化 Webサービス構想案

作成日：2026-10-28  
更新日：2026-10-29  
版：v0.3（静的Web構成の前提を追加・実装前）

## 1. 目的と結論

自治体が保有する施設・設備・点検・費用等のデータを、共通の定義で作成・検証・変換・提供するサービスを想定する。現段階の資料で**画面構成、出力規則、検証方式、試作品の設計は可能**。複数自治体が実データを交換する運用や一般公開の開始には、正本データモデル、コード、識別子、公開方針の確定が必要である。

サービスの中心は「標準プロファイル」である。プロファイルは、対象データの表、必須列、選択可能な列、型、コード、参照関係、列順、版を固定した機械可読な定義とする。利用者が任意列を選んでも、共通の必須列・意味・型は変更できない。自治体独自列は拡張名前空間で区別する。

## 2. 想定利用者と利用の流れ

利用者：自治体の施設所管課、資産管理・防災・情報政策部門、データ公開担当者。データの閲覧者・再利用者は公開された配布物と定義書を利用する。

1. 対象領域と標準プロファイルの版を選ぶ（例：施設基本、設備、点検・修繕）。
2. 必須列を確認し、推奨・任意列を追加選択する。選択結果を自治体の出力設定として保存する。
3. 空のCSVテンプレート、列定義、統制語彙・コードリスト、検証規則、サンプルデータを取得する。
4. 手持ちのExcel/CSVを取り込み、元列と標準列を対応付ける。変換候補・変換根拠・未確定箇所を画面で確認する。
5. 型、必須、コード、主キー・外部キー、期間・単位、表間整合性を検証し、行・列・原因・修正案を返す。
6. 担当者が結果を承認して標準形式で出力する。公開する場合は別途、公開対象とライセンスを選択し、公開用検査を通して公開する。

## 4. 出力データの設計原則

- **表の単位を固定する。** 施設1行、設備個体1行、点検1行などを混在させない。施設と建物の多対多、施設と複数の関連組織などは関係表で表す。
- **必須・推奨・任意を分ける。** 「任意項目の選択」は共有必須列の削除を意味しない。自治体ごとの選択列一覧をプロファイルとして同梱する。
- **識別子を明示する。** 自治体をまたいで同じIDが衝突しないよう、発行主体・適用範囲・形式・変更方針を定義する。現行のID生成記述は未確定として扱う。
- **文字コードと値表現を固定する。** UTF-8、列名、列順、空値、日付、真偽、数値・単位、コード値、改行、CSVエスケープをプロファイル版ごとに定義する。
- **コードと版を同梱する。** コードリストID、版、許容値を参照できるようにし、廃止値や自治体独自値を区別する。
- **同じ正本から生成する。** 人間向け定義書、空テンプレート、検証規則、サンプル、メタデータを同一のモデル版から生成する。

最初の配布形式は複数CSVとマニフェスト（プロファイルID・モデル版・出力日時・表一覧）をまとめたZIPを提案する。Excelは入力支援用、APIとJSONは後続拡張とする。CSVの列定義・制約の機械可読化にはW3C CSV on the Webのメタデータ仕様を候補とする。RDF/JSON-LDを提供する段階では別途SHACLによる検証を検討する。

## 6. 検証と変換の境界

検証は、(A) ファイル構文・列、(B) 各値の型・必須・範囲・コード、(C) PK重複・FK参照・表間関係・期間、(D) 公開対象の権利・非公開列・位置情報等の確認、の順に行う。エラーと警告を分け、警告を承認して出力した場合は理由を記録する。

変換では元ファイルを保持し、対応表と変換履歴を残す。列名や値の似方から候補を提案できるが、「施設」と「建物」、「設備台数」と「設備個体」、「計画費用」と「実績費用」などは自動的に同一視しない。欠けた必須値を推測で作成しない。識別子を新規発行する場合は規則と発行履歴を残す。

## 7. 公開とメタデータ

公開はデータ取込と独立した操作にする。既定は非公開。一般公開前に公開対象列・行、個人情報や防災上の詳細、ライセンス、第三者権利、更新責任者を確認する。初期の静的構成では、公開用ファイルを利用者が生成・確認してダウンロードするところまでとし、Webサービスからの公開・配信、限定共有、公開済み版の管理は別途運用または後続機能とする。

メタデータは現行の[メタデータガイドライン](../00_ガイドライン/05_施設管理_メタデータガイドライン.md)に従い、データセットと配布物を分ける。自動採取できる値（版、更新日時、形式、ファイルサイズ、検証結果等）と人が決める値（タイトル、説明、提供者、対象範囲、ライセンス、公開可否等）を分けて管理する。未公開のデータに架空の公開URL・公開日を設定しない。

- 現行ver5 CSV（138項目）、コード定義ver8、同義語ver4、クラス図を使った試作画面・テンプレート・限定的な検証規則の作成。
- 施設基本・設備・点検など少数の表を対象にした、架空データでの取込から出力までの実証。

### 実データ交換・公開前に決めること

1. 正本のクラス名と物理テーブル名、プレフィックス、設備種別名など、現行CSV・クラス図間の不整合を解消する。
2. クラス、属性、関係、元項目対応、単位、値域、計算式、コードの版を正本から再現できるようにする。
3. 共通必須プロファイルの範囲、ID発行主体・衝突防止、自治体独自列の規則、版互換性を定義する。
4. 代表的な複数自治体の実ファイルを用い、対応付け可能性、欠損、コード差、更新方法を確認する。実ファイルの利用は各自治体の許可と管理方法が決まってから行う。
5. 公開対象、権限、承認者、ライセンス、公開停止・訂正手順を自治体の運用に合わせて決める。

## 9. 追加検討事項（2026-10-29）

### 9.1 統制語彙リスト・コードリストの閲覧とCSV出力

リスト一覧、各値の符号・ラベル・説明・出典・参照規格・確認状態・版を閲覧できるようにする。まずはリストごとのCSVと全リスト一括CSVを出力する。データ本体のテンプレートと同じモデル版に対応するリスト版を選べるようにし、出力物にはリストID、リスト版、取得日時、列定義を添える。

「統制語彙」は候補語・優先語・別名・関連語・上位下位関係を持ち得る。「コードリスト」は符号と許容値の集合として扱う。現行のコード定義CSVには両者や論理値が混在するため、公開用の区分・採用状態・符号の有無を確認してから出力規則を決める。未確定の候補を正式な許容値として表示しない。

**判定：実装可能。** 現行の`06_データモデルCSV/施設管理コード定義ver8.csv`を試作入力に利用できる。正式提供には、語彙とコードの区分、値の採否・版・一意性、外部資料のライセンス確認が必要。

### 9.2 GitHub上のマスターCSVへの追従

初期入力は、この作業フォルダ内の次の4ファイルとする。将来これらを公開用GitHubリポジトリで管理し、GitHub上の採用コミットをWebサービスのマスター版とする想定である。

| 入力 | 現行ファイル | 主な用途 |
| --- | --- | --- |
| データモデル | `06_データモデルCSV/施設管理データモデルver5.csv` | クラス・項目、型、必須、キー、コード参照の定義 |
| コード定義 | `06_データモデルCSV/施設管理コード定義ver8.csv` | コードリスト・統制語彙の定義とCSV出力 |
| 同義語詳細辞書 | `06_データモデルCSV/施設管理同義語詳細辞書ver4.csv` | 名称検索、別名候補、元データ項目との対応支援 |
| 地方公共団体コード | `06_データモデルCSV/全国地方公共団体コードver2.csv` | 自治体コードの参照・検証 |

現行のファイル名に含まれる`ver5`等は初期入力を識別するもの。GitHub移行後の版管理はコミットと必要に応じたリリースタグで行う。リポジトリ内でファイル名を固定するかは移行時に決める。4ファイルは同一の採用コミットから一式として取得し、ファイルごとに異なる時点の版を混在させない。

GitHub追従は後続段階とする。実行時のブラウザからGitHub APIや外部URLを呼び出さない。将来は公開前のビルド工程で「変更検知 → 固定したコミットから取得 → CSV構文・ID重複・参照・型・版互換性を検査 → 差分を表示 → 管理者が採用 → テンプレート、検証規則、リスト、定義書、関係図を再生成 → 静的ファイルとして公開」の順とする。取得したコミットIDと採用時刻を記録し、旧版のダウンロード・検証を維持する。破壊的な列名変更やコード廃止は既存データへの影響を表示し、無条件に本番へ反映しない。同期失敗時は最後に採用した版を使い続けられるようにする。

公開用GitHubリポジトリの作成・アップロードは別作業であり、この構想案では実施しない。GitHub側の更新権限、採用承認者、更新通知方法、リポジトリのライセンス、リリースタグ、CSVの仕様と検査規則を決める必要がある。

**判定：設計・実装可能。** 初期入力の4ファイルは存在する。実際のGitHub追従検証は公開用リポジトリが用意された後。サービス側は特定のコミットを参照し、公開中のデータ形式が突然変わらないようにする。

### 9.3 クラス間リレーションの図示

クラスをノード、関係を線として、関連名・方向・両端多重度・対応FK・根拠となるモデル版を表示する。クラスを選ぶと属性、説明、参照先、関連するコードリストを開けるようにする。全体図に加え、施設基本・設備・点検等の領域別表示と、直接つながるクラスだけの絞り込みを用意する。

初期構成では正本の関係定義から静的なグラフデータを生成し、ブラウザ内のJavaScriptとSVG等で図示する。Neo4jをブラウザから直接接続しない。将来、サーバー側の検索・探索が必要になった段階でNeo4jを評価する。現行Mermaidクラス図は表示の参考にできるが、図の文章を唯一の正本として機械解析する設計にはしない。関係ID、始点・終点クラスID、関係種別、両端多重度、FKを構造化した正本が必要である。

**判定：図示の試作は可能。** 正確な自動更新と検証には、クラス・関係の構造化定義を整備する必要がある。Neo4jを使う場合は、配置、アクセス権、運用コストを別途評価する。

### 9.4 追加要件による作業順序

1. 静的HTML・JavaScript構成と、ブラウザ内で扱うデータ範囲を定める。
2. クラス・属性・関係、語彙・コード、版の機械可読な定義と検査規則を整備する。
3. 語彙・コードCSV出力と関係図を、固定したモデル版から試作する。
4. GitHub移行後、ビルド時のマスター追従と版切替・差分表示を加える。
5. 複数自治体の試行を経て、公開用のデータ・メタデータ・リストを提供する。

## 10. 初期のプログラム構成と外部依存の境界

### 10.1 実行方式

初期版は**静的HTML、CSS、分離したJavaScriptファイル、同梱したモデルデータ**で構成する。利用者のブラウザ内で項目選択、CSV生成、ファイル読込、検証、関係図表示を実行する。実行時のAPI、外部データベース、ログイン、サーバーへの利用者データ送信は設けない。開発時はこのフォルダ配下で静的ファイルを作り、ローカルの静的サーバーで動作確認する。`file://`からの直接起動だけを動作条件にしない。

```text
静的ホストまたはローカル静的サーバー
  ├─ index.html                 画面の入口
  ├─ css/                      同梱スタイル
  ├─ js/                       画面、CSV入出力、検証、図示を分離したJavaScript
  └─ data/                     固定版のモデル・コード・同義語・自治体コードと版情報
                                  ↓ 同一オリジンから読込
利用者のブラウザ                 ファイル選択・変換・検証・ダウンロード
```

ソースの4 CSVは読み取り専用の入力とし、画面用データや検証規則はその固定版から生成する。画面上で利用者が指定する手持ちデータはブラウザ内で処理し、明示したダウンロード以外の通信を行わない。データを長期保存する機能は初期版に含めない。

### 10.2 外部の影響を受けにくくする条件

- 実行時に外部API、CDN、外部フォント、外部画像、第三者のJavaScriptを読み込まない。ライブラリが必要な場合は採用版とライセンスを確認し、同梱・固定する。
- 任意の外部URLからモデルを取得しない。アプリが使用するモデル版は配布物に同梱し、版・入力ファイル識別情報を画面に表示する。
- CSVと利用者入力を命令やHTMLとして実行しない。表示時はテキストとして扱い、CSV出力時は式として解釈され得る先頭文字への対策を定める。
- 静的ホスト側で可能ならContent Security Policy等により、スクリプト・通信先・埋込先を制限する。設定値は実装時にブラウザで検証する。
- 入力サイズ上限とエラー処理を定め、巨大・不正CSVで画面が停止しないようにする。変換前後の値と検証結果を利用者に示す。
- 依存ライブラリやビルド用ツールの更新は明示的に行い、生成物の差分を確認する。実行時に自動更新させない。

### 10.3 この構成で可能なことと境界

静的構成で、モデル検索、項目選択、テンプレート・語彙CSV出力、ローカルファイルの変換・検証、架空サンプル、関係図、メタデータの下書き生成は実現できる。一方、自治体の利用者認証、共有された保存領域、承認ワークフロー、一般公開の配信管理、リアルタイムのGitHub追従、Neo4jへの直接接続にはサーバー側の仕組みが必要になる。これらは初期版の画面で実装済みと見せず、後続段階または人が行う運用として明記する。

公開用ファイルは初期版で生成できるが、実際の一般公開は自治体が内容を確認し、別途管理する公開先へ配置する。静的サイトに手持ちデータを読み込ませても、その操作だけで一般公開されることはない。
