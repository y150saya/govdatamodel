# 自治体施設管理Webサービス 次段階整理

作成日：2026-10-29  
版：v0.2  
状態：構想案v0.3からの試作範囲案。実装・公開の決定ではない。

## 1. いま固定できる前提

- 利用者は自治体の施設管理担当者。共通の必須項目を保ったまま推奨・任意項目を選択する。
- 初期入力は次の4ファイル。いずれもこの作業フォルダの`06_データモデルCSV`配下にある。
  - `施設管理データモデルver5.csv`：138行
  - `施設管理コード定義ver8.csv`：578行、区分はコードリスト278行・統制語彙リスト296行・論理値4行、リストIDは43種類
  - `施設管理同義語詳細辞書ver4.csv`：616行
  - `全国地方公共団体コードver2.csv`：1,965行
- 初期の実行方式は静的HTML、CSS、分離したJavaScriptファイル、同梱したモデルデータ。実行時APIと外部データベースを使わない。
- 将来は4ファイルをGitHubで版管理し、採用した同一コミットの一式をビルド時に取り込む。初期版のブラウザからGitHubへ接続しない。
- 手持ちデータはブラウザ内で処理し、サーバーに送らない。初期版では公開用ファイルの生成まで行い、一般公開は別の運用で承認・配置する。

## 2. 最初の試作で確認する価値

最初の試作は**「モデルを読む → 項目を選ぶ → CSV一式を出す → 架空データを検証する」**までを一続きで確認する。対象は施設基本と設備を第一候補とする。入力は上記4ファイルのローカルな固定スナップショットとし、実自治体データの収集や一般公開は含めない。すべての画面機能は同梱したJavaScriptでブラウザ内実行する。

| 機能 | 試作での具体的な到達点 | 確認方法 |
| --- | --- | --- |
| モデル閲覧 | クラス・項目・型・必須区分・説明・参照リストを検索できる | CSVの内部管理IDで元行に戻れる |
| 項目選択 | 必須列を保持し、推奨・任意列を選んで保存できる | 選択結果にプロファイルID・入力版を記録する |
| CSV出力 | 空テンプレート、列定義、対象リスト、マニフェストを出せる | 再生成して列順・型・版が一致する |
| 語彙・コード出力 | 区分別・リスト別のCSVを出せる | コードリストIDとリスト名で元定義に追跡できる |
| 架空サンプル | 施設と設備のPK/FKが整合した例と、意図的なエラー例を配布する | 正常例は通過し、エラー例は位置・理由が表示される |
| 検証 | 必須、型、コード、重複PK、FK、自治体コードを検査する | 同じ入力・同じ版で結果が再現する |
| 関係図 | 施設・設備等の関係を表示し、FKと多重度の出典を見られる | 図の各線から元定義・図の根拠へ戻れる |

## 3. 試作で仮定してよいこと・決めてから進めること

| 論点 | 試作上の扱い | 正式運用前の決定 |
| --- | --- | --- |
| 正本 | 4ファイルを固定スナップショットとして読み込む | GitHubリポジトリの管理主体、配置、採用コミットの運用 |
| クラス・関係 | クラス図を表示上の参照とし、関係は試作対象分を明示的に構造化する | クラス・関係の正本と多重度・FKの機械可読定義 |
| ID | 既存値の形式と重複を検査し、推測生成しない | 自治体間で衝突しない発行・変更規則 |
| 統制語彙 | 候補と採用値を区別して表示する | 採用状態、版、外部出典の利用条件 |
| プロファイル | 試作対象の共通必須列を暫定設定する | 複数自治体で合意した共通必須・任意の境界 |
| データ変換 | 列対応候補と変換差分の表示までを次段階とする | 曖昧な対応の承認者と変換規則 |
| メタデータ | 出力日時・形式・入力版などを自動記録する | 提供者、対象範囲、ライセンス、公開権限 |
| 一般公開 | 画面・権限の設計を行う | 自治体ごとの公開判断、審査、取下げ手順 |
| 実行方式 | HTML・CSS・JavaScriptとモデルデータを同梱。通信は同一オリジンの静的資産取得に限定する | 公開先のホスト設定、Content Security Policy、対応ブラウザ |
| 外部依存 | 実行時の外部API・CDN・外部フォントを使わない | 必要なライブラリの固定版・ライセンス・更新手順 |

## 4. 実装に入る前の最小タスク

1. HTML・CSS・JavaScriptのファイル構成、静的モデルデータの生成手順、実行時通信の制限を定義する。
2. 4入力ファイルと現行クラス図の対応を点検し、クラス英語名、設備種別名、プレフィックス、関係定義の不整合を一覧化する。
3. 施設基本と設備について、出力表の行単位・必須列・選択列・FK・コード参照を暫定プロファイルとして定義する。
4. 検証規則を機械可読にし、架空の正常例とエラー例で期待結果を定める。
5. 固定版からCSV、語彙・コード、関係図を生成する試作を行い、外部APIなしで動作することを確認する。
6. 試作結果を見て、GitHubのビルド時追従、実データ変換、公開機能の順序と要件を更新する。

## 5. 現時点の判断

9条件と追加の3条件は、サービス構想として矛盾なく整理できる。いま追加のアイデアを待つより、**施設基本＋設備の小さな一貫した試作**で、正本から出力・検証までを再現できるか確認するのが次の有効な作業となる。試作で見つかった定義上の不足を構想案へ戻して修正する。
