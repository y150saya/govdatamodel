# 施設管理_メタデータガイドライン

## 1. 目的

本ガイドラインは、行政の施設管理データモデルに関するデータセットを識別、検索、管理および再利用できるようにするため、データセット単位のメタデータ整備方針を定めるものである。

メタデータ語彙はW3C Data Catalog Vocabulary（DCAT）Version 3を基本とし、DCATで利用されるDublin Core Metadata Terms（DCMI Metadata Terms）との共通項目を優先して整備する。

### 1.1 適用範囲

- 当面は `dcat:Dataset` に相当するデータセット単位のメタデータを中心とする。
- DCATのクラス名を記載する場合は、正式な表記である `Dataset` を使用し、`DataSet` とは表記しない。
- CSV、Excel、HTML等の配布形式は `dcat:Distribution` として必要最小限のメタデータを整備する。
- `dcat:Catalog`、`dcat:CatalogRecord`、`dcat:DataService`および`dcat:DatasetSeries`の詳細な実装は、必要性を確認した後に拡張する。
- クラスやプロパティ単位の定義、単位、コードリストおよび統制語彙の詳細は、データモデルCSVおよび各ガイドラインで管理し、本ガイドラインではデータセットからの参照関係を扱う。

### 1.2 本ガイドラインの状態

- 本ガイドラインは初期ドラフトとする。
- メタデータ項目の採否、必須区分および多重度は、データモデルと成果物が確定した最終工程で調整する。
- 本文中の「中核候補」「条件付き候補」「拡張候補」は、最終的な必須・推奨・任意を確定する前の分類とする。

## 2. 参照標準と優先順位

### 2.1 基準とする仕様

1. **W3C DCAT Version 3**
   - データセット、配布形式、カタログおよびデータサービスを記述する基本語彙として使用する。
   - 参照先: https://www.w3.org/TR/vocab-dcat-3/
2. **DCMI Metadata Terms**
   - タイトル、説明、識別子、提供者、日付、権利、ライセンス等の共通メタデータ語彙として使用する。
   - 参照先: https://www.dublincore.org/specifications/dublin-core/dcmi-terms/
3. **コード整備ガイド案 Appendix C**
   - 本プロジェクトにおけるDCAT、Dublin Coreおよび日本語項目名の対応を確認するための優先参考資料として使用する。
   - 特に「C.6 参考資料：公開データの管理情報（メタデータ）」の対応表を参照する。
   - 参照先: `05_参考/コード整備ガイド案/04_Appendix_C_ID体系・コードリストのデータモデルと実装例_20260611.md`

### 2.2 Appendix Cの扱い

- Appendix CのC.6に記載された「データ項目」「項目説明」「プロパティ名」「項目元」の対応を、本ガイドラインの日本語項目名を決めるための基礎とする。
- Appendix Cで使用される `dcterms:` と、本ガイドラインで使用する `dct:` は、いずれも `http://purl.org/dc/terms/` を示す同一の名前空間プレフィックスとする。
- 本プロジェクトでは短縮形を `dct:` に統一する。外部資料の引用または変換時には、`dcterms:` を同義のプレフィックスとして受け入れる。
- Appendix Cは案であるため、W3C DCAT 3またはDCMI Metadata Termsの定義と異なる場合は、公式仕様を優先し、差異を記録する。
- 特に `dct:type` はデータセットの性質またはジャンルを表し、CSV、Excel等のファイル形式はDistributionの `dct:format` または `dcat:mediaType` で表す。

### 2.3 適用の優先順位

1. 法令、条例、行政機関の公開ルールおよび情報管理上の制約
2. 本プロジェクトで確定した利用目的と要件
3. W3C DCAT 3およびDCMI Metadata Terms
4. コード整備ガイド案 Appendix C
5. プロジェクト固有の拡張項目

標準項目で表現できない場合に限り、意味、必要性および標準項目との対応関係を明記して独自項目を追加する。

## 3. メタデータの対象

| 対象 | RDFクラス | 本プロジェクトでの例 | 初期対応 |
| :--- | :--- | :--- | :--- |
| データセット | `dcat:Dataset` | 施設管理データモデル | 中心対象 |
| 配布形式 | `dcat:Distribution` | データモデルCSV、コード定義CSV、Excel、HTML | 必要最小限 |
| カタログ | `dcat:Catalog` | 複数データセットを公開する一覧 | 将来拡張 |
| カタログレコード | `dcat:CatalogRecord` | カタログ上の登録情報 | 将来拡張 |
| データサービス | `dcat:DataService` | APIによるデータモデルまたはデータの提供 | 将来拡張 |
| データセット系列 | `dcat:DatasetSeries` | 年度別・版別に継続公開するデータセット群 | 将来拡張 |

同一内容をCSV、Excel、HTML等の異なる形式で提供する場合は、原則として1つの `dcat:Dataset` に対する複数の `dcat:Distribution` として扱う。内容や対象期間が異なる場合は、別データセットまたはデータセット系列として扱うかを確認する。

DCATのデータセット記述で利用でき、Dublin Core Termsとの共通性が高い項目を優先する。

| :--- | :--- | :--- | :--- | :--- |
| 中核候補 | 管理ID | `dct:identifier` | 文字列またはURI | データセットを一意かつ継続的に識別する。 |
| 中核候補 | タイトル | `dct:title` | 言語タグ付き文字列 | 内容を簡潔かつ具体的に表す。 |
| 条件付き候補 | サブタイトル | `dct:alternative` | 言語タグ付き文字列 | 正式タイトルを補足する別タイトルが必要な場合に記載する。 |
| 中核候補 | 説明 | `dct:description` | 言語タグ付き文字列 | 目的、対象範囲、内容および想定用途を記載する。 |
| 中核候補 | 提供者 | `dct:publisher` | 組織を表すURIまたは構造化値 | データセットの提供または公開責任を持つ組織を記載する。 |
| 中核候補 | 作成者 | `dct:creator` | 組織または個人を表すURIまたは構造化値 | データセットの作成責任主体を記載する。提供者と同じ場合も役割を区別する。 |
| 中核候補 | 公開日 | `dct:issued` | `xsd:date`または`xsd:dateTime` | 最初に正式公開した日を記載する。 |
| 中核候補 | 最終更新日 | `dct:modified` | `xsd:date`または`xsd:dateTime` | データセット本体を最後に変更した日を記載する。 |
| 中核候補 | 言語 | `dct:language` | 言語コードまたはURI | 原則としてBCP 47等の標準的な言語タグを使用する。 |
| 条件付き候補 | 主題 | `dct:subject` | 統制語彙URIまたは文字列 | 可能な場合は標準的な統制語彙を使用する。 |
| 条件付き候補 | タイプ | `dct:type` | 統制語彙URI | データセットの性質またはジャンルを表す。ファイル形式には使用しない。 |
| 条件付き候補 | 対象地域 | `dct:spatial` | 地理識別子またはURI | 対象自治体、行政区域または地理的範囲を記載する。 |
| 条件付き候補 | 対象期間 | `dct:temporal` | 期間を表す構造化値 | データが対象とする期間を記載する。 |
| 条件付き候補 | 更新頻度 | `dct:accrualPeriodicity` | 統制語彙URI | 定期更新する場合に記載する。 |
| 条件付き候補 | 準拠する標準 | `dct:conformsTo` | 標準またはプロファイルのURI | DCAT、DCMI、GIF、業務標準等への準拠関係を記載する。 |
| 条件付き候補 | 出典 | `dct:source` | URIまたは識別子 | 元Excel、既存データモデル、外部標準等の主要な出典を記載する。 |
| 条件付き候補 | 来歴情報 | `dct:provenance` | URIまたは説明 | 作成・変換・承認の経緯が必要な場合に記載する。 |
| 条件付き候補 | 公開範囲 | `dct:accessRights` | 権利文書のURIまたは統制値 | 公開、制限付き公開、非公開等のアクセス範囲を記載する。 |
| 条件付き候補 | 公開条件 | `dct:rights` | 権利文書のURIまたは説明 | 制限付き公開の条件、権利情報および利用上の制約を記載する。 |

Dublin Core Termsだけでは表しにくく、データセットの発見または配布に有効な項目に限定して追加する。

| 日本語項目名 | プロパティ | 対象 | 記述方針 |
| :--- | :--- | :--- | :--- |
| キーワード | `dcat:keyword` | Dataset | 検索用の自由語。統制語彙による主題とは区別する。 |
| 分類 | `dcat:theme` | Dataset | カタログで採用するテーマ分類のURIを使用する。 |
| 連絡先情報 | `dcat:contactPoint` | Dataset | データ内容や利用方法の問い合わせ先を記載する。 |
| ランディングページ | `dcat:landingPage` | Dataset | 説明、定義書または利用案内を掲載するページを記載する。 |

| 品質評価 | `dqv:hasQualityAnnotation` | Dataset | 評価方法と注釈の構造が確定した場合に記載する。 |

## 8. 記述ルール

### 8.1 識別子

- データセットには、版やファイル名の変更だけで不用意に変わらない永続的な管理IDを付与する。
- URIを付与する場合は、名前空間、所有者、維持方法および廃止時の扱いを決める。
- 配布ファイルの識別子とデータセットの識別子を混同しない。

### 8.2 タイトルおよび説明

- タイトルは、組織内だけで通用する略称に依存せず、対象と内容を識別できる名称とする。
- 説明には、目的、対象範囲、収録内容、主要な除外事項および想定する利用方法を記載する。
- 日本語と英語を併記する場合は、言語タグまたは言語欄で区別する。

### 8.3 組織および責任

- 提供者、作成者、管理担当および問い合わせ先の役割を区別する。
- 組織名は可能な限り標準的な組織識別子または統一名称を使用する。
- 担当者個人に依存する連絡先より、継続的に管理される組織窓口を優先する。

### 8.4 日付およびバージョン

- 日付はISO 8601に従い、`YYYY-MM-DD`またはタイムゾーンを含む日時で記載する。
- データセット本体の最終更新日と、カタログレコードの更新日は区別する。
- バージョン番号、公開日、最終更新日および旧版との関係が矛盾しないようにする。

### 8.5 ライセンス、権利およびアクセス制約

- ライセンスは可能な限りライセンス文書の正式なURIで示す。
- `dct:license`、`dct:rights`および`dct:accessRights`を区別する。
- 非公開または庁内限定のデータセットでは、ライセンスだけでなくアクセス権と取扱区分を明示する。
- 元データ、外部コードリスト、統制語彙、画像、文章等の第三者権利を確認し、成果物全体に適用できる条件を判断する。

### 8.6 出典、標準および統制語彙

- 元Excelや派生元データは `dct:source` の候補とする。
- 準拠する仕様、ガイドラインおよびデータモデルは `dct:conformsTo` の候補とする。
- 参照しただけの資料と、正式に準拠した標準を区別する。
- 外部コードリストおよび統制語彙は、名称、管理主体、バージョンまたは適用時点、URI、ライセンスおよび確認日を記録する。

## 9. 運用管理項目

次の項目はDCAT/DCMIへの公開項目とは別に、メタデータを維持するための内部管理項目として保持する。

| 管理項目 | 内容 |
| :--- | :--- |
| 確定状態 | 未確認、確認中、確定、廃止等 |
| 管理担当 | 内容の確認と更新を担当する組織または役割 |
| 確認日 | 値、出典および外部標準を最後に確認した日 |
| 確認者 | 確認を実施した組織または役割 |
| 根拠 | 決定根拠となる文書、URL、会議記録等 |
| 備考 | 残課題、適用条件、例外等 |

公開用メタデータと内部管理項目を混在させず、出力時に選択できるようにする。

## 10. 本プロジェクトでの対応関係

| 成果物・情報 | メタデータ上の扱い |
| :--- | :--- |
| 施設管理データモデル全体 | `dcat:Dataset` |
| 元Excel | `dct:source`で参照する候補 |
| 施設管理データモデルCSV | `dcat:Distribution` |
| 施設管理コード定義CSV | Datasetの一部または関連するDistribution。最終構成で決定する。 |
| 施設管理データモデル定義書.html | 説明用Distributionまたは`dcat:landingPage`。公開方法に応じて決定する。 |
| Mermaidクラス図 | `dct:relation`で参照する関連資料の候補 |
| 外部コードリスト・統制語彙 | `dct:conformsTo`、`dct:relation`または各属性の参照先として管理する。 |

### 10.1 コードリスト自体のメタデータ

- コードリストの概念体系は、Appendix Cに従い `skos:ConceptScheme` として表現することを基本とする。
- コードリスト自体のタイトル、説明、提供者、作成日、公開日、最終更新日、ライセンスおよび出典には、必要に応じて `dct:title`、`dct:description`、`dct:publisher`、`dct:created`、`dct:issued`、`dct:modified`、`dct:license`、`dct:source` を使用する。
- コードリストをデータカタログで公開する場合は、コードリストの概念体系と、その公開単位である `dcat:Dataset` および配布ファイルである `dcat:Distribution` を区別する。
- 外部コードリストを参照するだけの場合は、内容を複製せず、管理主体、版または適用時点、参照URIおよびライセンスを記録する。

## 11. 整備手順

1. メタデータの対象となるデータセットと配布形式を確定する。
2. Dublin Core Termsと共通する中核候補を入力する。
3. 出典、提供者、管理主体、日付、バージョン、ライセンスおよび権利を確認する。
4. 対象地域、対象期間、更新頻度、主題および準拠標準を確認する。
5. 必要なDCAT固有項目だけを追加する。
6. 各値の根拠、確認日および確定状態を記録する。
7. データモデル、CSV、HTMLおよびクラス図が確定した後、項目の必須・推奨・任意を最終調整する。
8. 最終的なメタデータをHTML定義書および必要な機械可読形式へ出力する。

## 12. 検証項目

- データセットと配布形式の識別子が重複または混同されていないこと。
- タイトルと説明から対象範囲を判断できること。
- 提供者、作成者、管理担当および問い合わせ先の役割が明確であること。
- 公開日、最終更新日、バージョンおよび旧版との関係が整合していること。
- ライセンス、権利およびアクセス制約が矛盾していないこと。
- 配布形式ごとの形式、URL、メディアタイプおよびライセンスが正しいこと。
- 外部コードリスト、統制語彙および標準の管理主体、版、URI、ライセンスおよび確認日が記録されていること。
- 架空のURI、未確認の標準名または暫定値を確定値として公開していないこと。
- 採用した必須項目に欠損がないこと。
